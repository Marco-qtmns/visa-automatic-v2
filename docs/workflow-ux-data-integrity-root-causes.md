## Priority reproduction

The funding rollback is reproducible with a synthetic `CanadaCase` containing both `trip.payer` and `trip.payer_details`: after both candidates are accepted, Apply attempts to insert two primary `FundingSource` rows for the same trip. Existing transaction handling correctly prevents partial canonical writes, but the target-resolution defect makes the valid workflow fail.

The missing-biography workflow is reproducible by initializing an applicant without `PersonBiography.sex` and `birth_country_code`: readiness emits blocking paths for both, while the former `CanonicalDecisionItem` rejected those field paths and the simplified UI had no controls for them. The same audit found missing ordinary employee inputs for current residence, passport, structured residential address, official application date, reviewed trip dates/purpose and available-funds fields; these now share the existing typed canonical/revision mechanism.
